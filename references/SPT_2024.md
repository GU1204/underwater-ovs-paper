# Abstract

- **[3]** 介绍视觉提示调优；指出提示初始化、提示长度和自监督预训练性能问题；转向分析提示与图像块 token 的相关性变化。
- **[3]** 发现两类 token 具有较高互信息；用下游 token 原型初始化提示；进一步简化 token 构建流程。
- **[3]** 实验验证整体优势；MAE 预训练下较 VPT 提升 10%—30%，并在多数任务超过全量微调；证明 SPT 对提示长度稳定且具备规模扩展性。
- **[2]** 探索下游数据量对调优方式的影响；提供开源代码。

## 3.4 Optimization for Token Construction

- **[3]** token 原型可近似训练数据及中间表示分布；候选 token 数量远大于提示长度；K-means 耗时甚至超过模型微调。
- **[1]** 引出两类更实用的提示构建策略。
- **[3]** 从随机批次中选取 token，并通过均值或最大池化输出 (N_p) 个提示；采用非重叠池化窗口。
- **[1]** 定义窗口大小、取整符号和批量大小。
- **[3]** 提出更简化的随机采样；随机选取一批各层图像块表示；从中均匀抽取 (N_p) 个初始提示。
- **[2]** 强调简化流程更适合下游任务；从参数量和时间成本两方面评估。
- **[3]** SPT仅额外调优和保存提示；不同任务共享预训练骨干；以 ViT-B 为例，Shallow 和 Deep 提示分别只占骨干参数的0.089%和0.21%。
- **[3]** 对比 token 原型的性能收益与聚类成本；CUB-200-2011上的 SPT-Deep K-means 最长需27.3天；池化和随机采样仅需数十秒。
- **[1]** 表1量化不同数据比例下的构建时间，并表明简化策略仍保持较好性能。

# 5 Discussion and Conclusion

- **[1]** 缺少对提示初始化策略的严格理论保证。

- **[2]** 提高训练初始阶段的提示—图像块互信息；改善收敛速度和精度，尤其适用于自监督骨干。

- **[2]** 总结对提示长度和模型规模的稳定性；确认这些性质同样适用于监督预训练。
