# 二、任务类型统计

这里按论文的**主要实验任务**编码；USE、PCA-Seg 这种明显跨任务论文单列为 Multi-task，避免重复计数。

| 主任务                                    | 论文数 | 占 42 篇  |
| ----------------------------------------- | ------ | --------- |
| Open-Vocabulary **Semantic** Segmentation | **34** | **81.0%** |
| Open-Vocabulary Instance Segmentation     | 2      | 4.8%      |
| Open-Vocabulary Panoptic Segmentation     | 2      | 4.8%      |
| Open-Vocabulary Part Segmentation         | 2      | 4.8%      |
| Universal / Multi-task OVS                | 2      | 4.8%      |

结论非常明确：**2024–2026 OVS 的事实主体仍然是 Open-Vocabulary Semantic Segmentation。**大量所谓 “OVS” 新方法实际是在解决 CLIP 的 dense representation / pixel-text alignment，然后统一在语义分割 benchmark 上比较；training-free CLIP dense prediction 在 2024–2026 尤其密集，例如 SCLIP、ProxyCLIP、ClearCLIP、CASS、LPOSS、ResCLIP、PEARL、Direct、RF-CLIP。([欧洲计算机视觉协会](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/08490.pdf?utm_source=chatgpt.com))

**Instance / Panoptic / Part 并没有形成和 OVSS 同等规模的统一 benchmark 生态。**Part 已逐渐形成 Pascal-Part-116 / ADE20K-Part-234 / PartImageNet + base/novel + hIoU 的协议；Panoptic 则基本沿用 PQ；Instance 仍更依赖具体领域数据和 AP family。([NeurIPS 会议论文集](https://proceedings.neurips.cc/paper_files/paper/2024/hash/f7f47a73d631c0410cbc2748a8015241-Abstract-Conference.html))

这个表里最值得注意的不是“ADE20K 第一”，而是其**角色分工**：

> **COCO-Stuff 更像训练源，ADE20K / Pascal Context / Pascal VOC 更像泛化测试集。**

也就是说，现代 OVSS 并不是普遍采用“在 ADE20K 划 seen/unseen 然后训练、测试”的范式，而是大量使用：
$$
\text{COCO-Stuff training}
\rightarrow
{\text{ADE20K, Pascal Context, Pascal VOC}}
$$
来验证**跨数据集、跨词汇迁移能力**。CAT-Seg、SED、EBSeg、ESC-Net、DPSeg 等都属于这条路线。([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2024/html/Cho_CAT-Seg_Cost_Aggregation_for_Open-Vocabulary_Semantic_Segmentation_CVPR_2024_paper.html?utm_source=chatgpt.com))

------

# 四、最常见的 Train → Evaluation Dataset 组合

## 1. COCO-Stuff → 五类经典 OVSS benchmarks

这是目前**训练型 OV Semantic Segmentation 最稳定、最标准化**的一套协议：
$$
\boxed{
\text{COCO-Stuff}
\rightarrow
A-847,\ A-150,\ PC-459,\ PC-59,\ PAS-20
}
$$
本次样本中至少 **9 篇**采用这套或非常接近的组合：

**CAT-Seg、SED、EBSeg、SCAN、MAFT+、ESC-Net、DPSeg、PCA-Seg、LoGoSeg。**([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2024/html/Cho_CAT-Seg_Cost_Aggregation_for_Open-Vocabulary_Semantic_Segmentation_CVPR_2024_paper.html?utm_source=chatgpt.com))

这里的 **A-150/A-847、PC-59/PC-459 并不是 seen/unseen split**。它们主要是不同 vocabulary size / annotation space 的 evaluation benchmark。

------

## 2. No training → standard 8-set

Training-free CLIP 方法则形成了另一套事实标准：

**含 background**

- PASCAL VOC21
- Pascal Context60
- COCO-Object

**不含 background**

- PASCAL VOC20
- Pascal Context59
- COCO-Stuff
- Cityscapes
- ADE20K

也就是：
$$
\boxed{
\text{Frozen CLIP / no task training}
\rightarrow
8\text{-dataset direct evaluation}
}
$$
SCLIP、ProxyCLIP、ClearCLIP、LaVG、FreeDA、CASS、LPOSS、CorrCLIP、SFP、FreeCP、ResCLIP、PEARL、Direct、GLA-CLIP、RF-CLIP 等基本都围绕这一范式展开。CLIPtrase 的主表则是一个相近的 **9-set** 变体，明确同时报告 background-inclusive 和 background-free label spaces。([arXiv](https://arxiv.org/html/2407.08268v1?utm_source=chatgpt.com))

**这个协议和 COCO-Stuff→five-benchmark 协议不应该混在一个排行榜里。**前者测试的是 frozen / training-free VLM 的 dense zero-shot 能力，后者允许在 COCO-Stuff 上进行 segmentation-specific training。

------

## 3. COCO-Panoptic → ADE20K Panoptic

Panoptic 的协议集中得多：
$$
\boxed{
\text{COCO-Panoptic}
\rightarrow
\text{ADE20K Panoptic}
}
$$
MAFT+、EOV-Seg、OVRCOAT 都出现了这一核心迁移关系；OVRCOAT又扩展到 Mapillary Vistas 和 Cityscapes，以测试更强的 cross-domain generalization。主指标均围绕 **PQ**。([AAAI](https://ojs.aaai.org/index.php/AAAI/article/view/32669?utm_source=chatgpt.com))

------

## 4. Part dataset base → base+novel

Part segmentation 不以 COCO-Stuff→ADE 为核心，而是更典型的 generalized zero-shot：
$$
\text{Base classes training}
\rightarrow
\text{Base + Novel evaluation}
$$
代表数据集包括：

- Pascal-Part-116
- ADE20K-Part-234
- PartImageNet

PartCATSeg 还测试了 **PartImageNet → Pascal-Part** 一类 cross-dataset generalization。这里 `seen/unseen mIoU + hIoU` 才真正成为核心协议。([NeurIPS 会议论文集](https://proceedings.neurips.cc/paper_files/paper/2024/hash/f7f47a73d631c0410cbc2748a8015241-Abstract-Conference.html))

------

## 5. Specialized-domain cross-dataset zero-shot

近两年还出现了一个值得关注的新方向：
$$
\text{general-domain / source-domain}
\rightarrow
\text{specialized-domain target}
$$
例如：

- **COCO → MARIS**：水下 open-vocabulary instance segmentation。([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2026/html/Li_MARIS_Marine_Open-Vocabulary_Instance_Segmentation_CVPR_2026_paper.html?utm_source=chatgpt.com))
- **Natural-image VLM → OpenEarthMap / LoveDA / Potsdam / …**：remote-sensing OVSS。SegEarth-OV 在 17 个遥感数据集上评测，其中 8 个是多类别 semantic segmentation benchmark。([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2025/html/Li_SegEarth-OV_Towards_Training-Free_Open-Vocabulary_Segmentation_for_Remote_Sensing_Images_CVPR_2025_paper.html?utm_source=chatgpt.com))
- **COCO-Panoptic → Mapillary / Cityscapes / ADE20K**：panoptic cross-domain。([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2026/html/Kormushev_Mitigating_Objectness_Bias_and_Region-to-Text_Misalignment_for_Open-Vocabulary_Panoptic_Segmentation_CVPR_2026_paper.html?utm_source=chatgpt.com))

------

# 五、指标使用频率

## Semantic Segmentation

在本次 **34 篇以 OV Semantic 为主任务的论文中，mIoU 是事实上的统一主指标**。
$$
\boxed{\text{OV Semantic Segmentation} \rightarrow \textbf{mIoU}}
$$
不同论文会额外报告 pAcc、per-class IoU 或新设计的指标。例如 SCAN 提出 SG-IoU，但其主流 benchmark 对比仍然建立在 mIoU 上。([arXiv](https://arxiv.org/abs/2312.04089?utm_source=chatgpt.com))

这里有一个容易误判的地方：

**`mIoU_seen / mIoU_unseen / hIoU` 并不是 2024–2026 主流 OVSS 论文的必选指标。**

原因是大量 OVSS 工作走的是：

> COCO-Stuff training → completely different evaluation label space

而不是：

> dataset 内 base classes training → base+novel testing。

所以它们直接在 target vocabulary 上算 **mIoU** 就足够构成主要 leaderboard。

------

## Part Segmentation

PartCLIPSeg、PartCATSeg，以及 PCA-Seg 的 part experiment 都明确体现了：
$$
\boxed{
mIoU_{seen},\quad
mIoU_{unseen},\quad
hIoU
}
$$
其中
$$
hIoU =
\frac{2;mIoU_{seen};mIoU_{unseen}}
{mIoU_{seen}+mIoU_{unseen}}
$$
在 **generalized base/novel setting** 中尤其重要，因为只提高 seen 或只提高 unseen 都可能造成误导。([NeurIPS 会议论文集](https://proceedings.neurips.cc/paper_files/paper/2024/hash/f7f47a73d631c0410cbc2748a8015241-Abstract-Conference.html))

------

## Instance Segmentation

本次纳入的 OV instance 工作虽然少，但指标非常稳定：
$$
\boxed{\text{OV Instance Segmentation}\rightarrow AP/mAP}
$$
MARIS 明确使用 **mAP / AP50 / AP75**，并根据 intersection / open-vocabulary 类别进行分析；SCORE 的主要比较同样是 AP/mAP family。([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2026/html/Li_MARIS_Marine_Open-Vocabulary_Instance_Segmentation_CVPR_2026_paper.html?utm_source=chatgpt.com))

所以对于 instance segmentation：

- **AP/mAP 是主指标**
- AP50 / AP75 是很自然的辅助指标
- 如果设计 seen/novel split，可额外给 AP_seen / AP_novel
- 但 **hIoU 并不适用于 instance segmentation 的主评价体系**

------

## Panoptic Segmentation

结论最明确：
$$
\boxed{\text{OV Panoptic Segmentation}\rightarrow PQ}
$$
并通常辅以：

- SQ
- RQ
- PQ_seen / PQ_unseen 或 known/unknown 分析

EOV-Seg、OVRCOAT 以及 MAFT+ 的 panoptic experiment 都沿用 PQ family。([AAAI](https://ojs.aaai.org/index.php/AAAI/article/view/32669?utm_source=chatgpt.com))

# 六、不同 OVS 子任务目前的标准实验范式

| Task                       | 最常见训练方式                                      | 最常见 Evaluation                          | 主指标                      | seen/unseen 是否核心                  |
| -------------------------- | --------------------------------------------------- | ------------------------------------------ | --------------------------- | ------------------------------------- |
| **OV Semantic**            | COCO-Stuff supervised；或 frozen CLIP training-free | ADE20K / Context / VOC / COCO / Cityscapes | **mIoU**                    | **通常不是必须**                      |
| **OV Part**                | dataset base classes                                | base + novel classes；cross-dataset        | **mIoU seen/unseen + hIoU** | **是**                                |
| **OV Instance**            | source-domain base classes / source dataset         | novel + generalized / cross-domain         | **AP / mAP**                | 推荐分开报告                          |
| **OV Panoptic**            | COCO-Panoptic                                       | ADE20K / Mapillary / Cityscapes            | **PQ**                      | 可报告，但并非每篇都作为唯一主表      |
| **Training-free OVSS**     | 无 task training；frozen CLIP/VFM                   | 多数据集直接测试                           | **mIoU**                    | 通常无显式 seen/unseen                |
| **Specialized-domain OVS** | general source 或少量 domain data                   | domain-specific datasets                   | mIoU 或 AP/PQ，取决于任务   | 应明确 source/target category overlap |

# 七、从统计结果看，最常见的五种实验范式

**第一类：COCO-Stuff supervised training → 多数据集 zero-shot。\**这是训练型 OVSS 的主流设计，最典型的是 CAT-Seg/SED 系列。验证的重点不是同数据集 novel class，而是\**训练 vocabulary 到 target vocabulary 的迁移**。([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2024/html/Cho_CAT-Seg_Cost_Aggregation_for_Open-Vocabulary_Semantic_Segmentation_CVPR_2024_paper.html?utm_source=chatgpt.com))

**第二类：Frozen CLIP → 8-set direct evaluation。**这是 2024–2026 增长最明显的范式。整个训练集概念甚至消失，论文关注的是“如何让 image-level CLIP 产生可靠的 pixel-level representation”。ProxyCLIP、ClearCLIP、CASS、ResCLIP、PEARL、Direct、RF-CLIP 都属于这条线。([欧洲计算机视觉协会](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/08490.pdf?utm_source=chatgpt.com))

**第三类：单数据集 base→base+novel generalized evaluation。**目前在 Open-Vocabulary Part Segmentation 中尤其典型，seen/unseen 与 harmonic mean 在这里才真正重要。([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2025/papers/Choi_Fine-Grained_Image-Text_Correspondence_with_Cost_Aggregation_for_Open-Vocabulary_Part_Segmentation_CVPR_2025_paper.pdf?utm_source=chatgpt.com))

**第四类：COCO-Panoptic → other panoptic datasets。**主要看 PQ，强调 objectness、region-language alignment 和跨数据集 vocabulary transfer。([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2026/html/Kormushev_Mitigating_Objectness_Bias_and_Region-to-Text_Misalignment_for_Open-Vocabulary_Panoptic_Segmentation_CVPR_2026_paper.html?utm_source=chatgpt.com))

**第五类：general domain → specialized domain。**遥感、水下等垂直场景正越来越多采用这一范式。SegEarth-OV 直接测试大量遥感数据，MARIS 同时给出 MARIS→MARIS 和 COCO→MARIS。这类实验中，**训练类别和测试类别的交集必须单独说明**，否则“zero-shot/open-vocabulary”的强度无法判断。([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2025/html/Li_SegEarth-OV_Towards_Training-Free_Open-Vocabulary_Segmentation_for_Remote_Sensing_Images_CVPR_2025_paper.html?utm_source=chatgpt.com))

# 八、对你后续数据集与实验设计最重要的结论

结合上面的统计，几个判断已经比较稳固。

**1. “开放词汇”并不意味着必须做一个固定的 seen/unseen split。**
对于现在最成熟的 OV Semantic Segmentation，反而是：

[
\boxed{\text{source-dataset training}+\text{cross-dataset zero-shot}}
]

最常见。

**2. 如果任务是 Open-Vocabulary Instance Segmentation，主指标应该跟 instance segmentation 走，而不是照搬 OVSS。**

比较自然的是：

[
\boxed{
AP,\ AP50,\ AP75
}
]

如果你还要证明 generalized open-vocabulary 能力，可以补：

[
AP_{seen},\quad AP_{novel},\quad AP_{all}
]

而不是把 mIoU/hIoU 当主指标。MARIS 的指标选择也支持这一点。([开放获取计算机视觉基金会](https://openaccess.thecvf.com/content/CVPR2026/html/Li_MARIS_Marine_Open-Vocabulary_Instance_Segmentation_CVPR_2026_paper.html?utm_source=chatgpt.com))

**3. 最有说服力的实验设计通常同时包含两个维度：**

[
\textbf{In-domain generalized evaluation}
]

训练 base categories，测试包含 base + novel；

加上

[
\textbf{Cross-dataset zero-shot evaluation}
]

在 dataset A 训练，在 dataset B **不微调**直接测试。

这种设计比单纯一个 base/novel split 更能支撑“open-vocabulary generalization”。

**4. COCO / ADE / VOC 的真正启示不是“必须使用这些数据集”，而是实验角色要分开。**
目前成熟 OVS benchmark 的共同特征是：

> **source dataset 用于学习 segmentation，target dataset 用于证明 vocabulary generalization。**

所以如果后续设计水下 OVS benchmark，更值得复制的是这个**实验结构**，而不是机械复制 COCO-Stuff/ADE20K 本身。

**5. 对水下 Open-Vocabulary Instance Segmentation，我会优先考虑一个三层协议：**

[
\boxed{
\text{Base-class Training}
\rightarrow
\text{Base+Novel In-domain Test}
\rightarrow
\text{Cross-dataset Zero-shot Test}
}
]

并分别报告：

[
AP_{all},\ AP_{base},\ AP_{novel},
AP50,\ AP75
]

这比只设一个 train/val，然后报告总 AP，更接近近三年开放词汇文献真正想证明的“已见类别不退化 + 未见类别可泛化 + 跨数据集仍能迁移”。

**一句话总结这轮统计：**近三年的 OVS 实验标准已经非常清晰——**Semantic 以 mIoU + 多数据集 zero-shot 为核心；Part 以 base/novel + hIoU 为核心；Instance 以 AP family 为核心；Panoptic 以 PQ 为核心；而“跨数据集直接测试”比“必须做 seen/unseen split”更能代表当前主流 Open-Vocabulary Segmentation 的实验范式。**
