## 1. UIIS / WaterMask [24]：通用水下 Instance Segmentation

这是这条数据链里比较早的**通用水下实例分割**数据集。

WaterMask 官方仓库给出的规模是 **4,628 张、7 类、pixel-level instance masks**。7 类是：

Fish、Reefs、Aquatic plants、Wrecks/Ruins、Human divers、Robots、Sea-floor。([GitHub](https://github.com/LiamLian0727/WaterMask?utm_source=chatgpt.com))

原始 WaterMask 论文对图像来源写得并不特别详细，但同一作者团队后来的 UWSAM 论文补充说：UIIS 最初有约 **25,000 张来自不同来源的候选水下图像**，之后使用 **UCIQE 和 UIQM 两个水下图像质量指标**进行筛选，最终保留 4,628 张高质量图像，其中 3,937 train、691 test/val。([arXiv](https://arxiv.org/html/2505.15581v2?utm_source=chatgpt.com))

所以它不是“作者自己一次性潜水拍了 4,628 张”，而是**多来源图像池 → 质量筛选 → 人工实例标注**。

这里的关键是它属于 **general instance segmentation**：

> 一张图片中所有属于目标类别的对象原则上都应该被标出来，而且同类别的不同鱼要分成不同 instance。

这与后面的 USIS10K/USIS16K 很不一样。

**UIIS 没有报告“多少张图片含两个以上不同类别”这一统计。**所以不能从论文得到 multi-class image count。

## 2. USIS10K [25]：不是普通 instance，而是 Salient Instance

USIS10K 的来源写得非常清楚。

作者先收集约 **30,000 张候选图像**，来自 Internet 和已有公开水下数据，覆盖：

水下图像增强数据，包括 Li et al. 2020 的 UIEB、Berman et al. 2021 的 underwater color restoration 数据；水下实例分割数据 **UIIS/WaterMask**；水下显著性数据 **USOD10K**；以及 Islam et al. 2020 的 underwater enhancement/super-resolution 数据。之后两名志愿者去掉重复、损坏以及没有显著目标的图像，留下约 **16,000 张进入标注阶段**，经过显著性和类别一致性筛选，最终得到 **10,632 张**。([arXiv](https://arxiv.org/html/2406.06039v1))

它的 7 类仍然比较粗：

**Fish / Reefs / Aquatic plants / Wrecks-Ruins / Human divers / Robots / Sea-floor**。([arXiv](https://arxiv.org/html/2406.06039v1))

但它最关键的区别是：**USIS10K 只标“显著实例”。**

例如一张图里可能有：

- 前景一条大鱼；
- 背景还有十条很小的鱼；
- 一大片珊瑚；
- 水下机器人。

如果人类视觉认为只有大鱼是 salient object，那么 USIS10K **可能只给大鱼 instance mask**，而不会像普通 instance segmentation 一样把所有实例都标出来。

作者处理从 UIIS 来的图片时甚至专门让 3 名志愿者对 UIIS 中每个 instance 进行“是否显著”的投票，只保留得到足够票数的实例；对于显著目标检测数据，则重新细分成 instance masks。([arXiv](https://arxiv.org/html/2406.06039v1))

它的实例密度统计是：

**1,731 张图像含超过 3 个 salient instances，占 16.3%；单图最大 9 个 salient instances。**此外 16.0% 的实例面积小于图像 1%，9.1% 的实例面积超过图像 30%。([arXiv](https://arxiv.org/html/2406.06039v1?utm_source=chatgpt.com))

但还是要注意：

**“>3 instances” ≠ “>3 categories”。**

例如一张图 6 条鱼都是 `Fish`，在 instance 层面是 6，在类别层面仍然只有 1 类。**USIS10K 没有公布 distinct categories per image 的统计。**

## 3. SUIM [15]：这几个里面唯一典型的 Semantic Segmentation

SUIM 和其他几个的数据结构差异很大。

它有 **1,525 张 train/val + 110 张 test = 1,635 张图像**，共有 8 个 semantic classes：

BW：background/waterbody
HD：human divers
PF：aquatic plants/sea-grass
WR：wrecks/ruins
RO：robots/AUV/ROV/instruments
RI：reefs/invertebrates
FV：fish/vertebrates
SR：sea-floor/rocks。([ar5iv](https://ar5iv.labs.arxiv.org/html/2004.01241))

图像主体来源是作者在**海洋探索和 underwater human-robot cooperative experiments** 中收集的自然水下图像，地点和水体类型很多。另外又加入了少量作者此前的 **EUVP、USR-248 和 UFO-120** 图像，也就是说 SUIM 本身已经是一个“现场实验数据 + 旧公开数据”的混合数据集。([ar5iv](https://ar5iv.labs.arxiv.org/html/2004.01241))

它服务的是 **semantic segmentation**，所以：

一张图中 10 条鱼全部被标成 `FV`，不会给你 10 个独立 fish instance ID。

这也是为什么 MARIS 如果利用 SUIM 图像，就不可能简单把 SUIM mask 搬过来——**必须重新做 instance-level annotation。**MARIS 明确说所有最终标注都是 pixel-accurate instance masks。([arXiv](https://arxiv.org/html/2510.15398v1))

SUIM 恰好对你问的“多类别”做了一些分析：论文 Fig. 2(a) 给出了**每个类别出现在多少张图中**，Fig. 2(b) 给出了**不同类别之间的 pairwise occurrence correlation**，所以它明确考虑了一张图中多种 semantic class 共现的问题。([ar5iv](https://ar5iv.labs.arxiv.org/html/2004.01241))

但作者**没有给一个汇总数字**，比如：

> “1,635 张中有 1,023 张包含 ≥2 个类别”

这样的数字没有报告。因此只能从原 annotation 重新统计才能准确回答。

## 4. USIS16K [13]：MARIS 最重要的“细粒度来源”

这一个和 MARIS 的关系最值得关注。

USIS16K 先从 **Google、Bing、Flickr 搜索水下目标相关图片和视频**；其次加入已有公开水下数据；再加入“underwater engineering tasks performed by robotic systems”中**机器人实际现场拍摄的水下图像**。总候选量超过 **35,000 张**，3 名志愿者去重、剔除损坏/低质量样本，留下 **16,151 张**。([arXiv](https://arxiv.org/html/2506.19472v1))

这里原论文有一个明显笔误：它写“representative images from the USIS16K dataset [12]”，但其参考文献 [12] 实际是 **USOD10K**，所以这里实际上应该是在说引入了 USOD10K 图像。([arXiv](https://arxiv.org/html/2506.19472v1))

之后 10 名标注员使用 eye-tracking 判断 salient objects，再依次提供：

classification → bounding box → salient segmentation → **instance mask**。([arXiv](https://arxiv.org/html/2506.19472v1))

因此 USIS16K 依然属于 **salient instance segmentation**，不是“场景里所有东西全部标”。

它最大的贡献是类别体系突然从 UIIS/USIS10K 的 7 类扩到：

**11 个 superclass + 158 个细粒度 object categories。**

11 个 superclass 包括 Human participant、Fish、Shellfish、Marine animals、Underwater trash、Underwater vehicles、Lost items、Underwater facilities、Underwater relics、Underwater wrecks、Others。单个细粒度类别对应的图像数大约在 **36–258 张**之间。([arXiv](https://arxiv.org/html/2506.19472v1))

而且 USIS16K 给了非常明确的单图实例数：

**14,700 张只有 1 个目标；1,228 张有 2 个；223 张有 ≥3 个。**

也就是至少

$$
1228+223=1451
$$
张、约 **9.0%** 的图片含多个 salient instances。([arXiv](https://arxiv.org/html/2506.19472v1))

但仍然不能说这 1,451 张都是“多类别图”。其中很多完全可能只是多条同种鱼。

## 5. UIIS10K / UWSAM [21]：把“显著实例数据”重新补全成通用 instance 数据

UIIS10K 的构造其实非常值得注意，因为它已经在做和 MARIS 类似的“多数据集重标注”。

作者先从 Internet 和公开水下数据集中收集约 **40,000 张**图片，来源包括：

underwater enhancement：UIEB、Berman underwater quantitative dataset、U-shape Transformer 相关数据；semantic segmentation：**SUIM**；instance segmentation：**UIIS + TrashCan**；saliency相关：Deep-SESR/UFO-120、**USOD10K、USIS10K**。([arXiv](https://arxiv.org/html/2505.15581v1))

所以要特别注意：

> **MARIS 引用的这几个数据集根本不是彼此独立的。**

例如：

`UIIS → USIS10K`
`UIIS → UIIS10K`
`USIS10K → UIIS10K`
`SUIM → UIIS10K`
`USOD10K → USIS10K / USIS16K / UIIS10K`

因此绝对不能把 4,628 + 10,632 + 1,635 + 16,151 + 10,048 当作五批互不重复的数据。

UIIS10K 对 40K 候选去重、去损坏、去非水下图后，留下约 **14,500 张进行标注**，最终筛成 **10,048 张**。([arXiv](https://arxiv.org/html/2505.15581v1))

更关键的是它对不同来源采用不同补标策略：

来自普通 instance segmentation 的图像：**修正原 mask、重新赋 category，并寻找漏标 instance**；来自 salient segmentation 的图像：不但修正已有 salient masks，还会**主动补标原来没有标出的 non-salient instances**；其他图像则重新标所有 objects of interest。使用 SAM/EfficientSAM 辅助，至少两人标、一人复核。([arXiv](https://arxiv.org/html/2505.15581v1))

所以 UIIS10K 已经从 USIS10K 的“只标显著目标”转回了 **general underwater instance segmentation**。

它有 **10 类、41,862 个 instance masks**：

Fish、Reptiles、Artiodactyla、Mollusk、Corals、Plants、Garbage、Ruins、Robots、Human。作者报告 Fish 和 Corals 数量最多。([arXiv](https://arxiv.org/html/2505.15581v1))

其中论文里的 `Artiodactyla` 明显很奇怪，因为描述实际上是 shrimp、crab、sea spider 这类有壳节肢动物；这个命名本身存在 taxonomy 问题。

实例密度非常高：

**22.83% 图像包含 >5 instances；8.45% 包含 >10；单图最多 81 个 instances。**作者解释主要来自鱼群和珊瑚簇。([arXiv](https://arxiv.org/html/2505.15581v1))

同样，没有公布“不同类别 ≥2”的图像数量。

# 6.  MARIS 

综合论文正文和附录，我认为可以把它理解成下面这个过程：

**第一层：收集已有水下图像资源。**
明确提及 UIIS/WaterMask、USIS10K、SUIM、USIS16K、UIIS10K。正文提到 UIIS + USIS10K，并说还包括 SUIM、USIS16K、UIIS10K；附录 F 则明确列 WaterMask、USIS16K、UWSAM/UIIS10K、SUIM，但没有再次写 USIS10K。这个细节说明作者并没有公开一个严格的“source → image count” provenance 表。([arXiv](https://arxiv.org/html/2510.15398v1))

**第二层：不是保留各数据集原来的粗类别，而是统一重标。**
UIIS 的 `Fish`、USIS10K 的 `Fish`、SUIM 的 `FV` 都太粗。MARIS 最终把 `Fish` superclass 细分成 **76 个具体种/类**，例如 Blue Parrotfish、Hammerhead Shark、Lionfish、Whale Shark、Butterflyfish 等。([arXiv](https://arxiv.org/html/2510.15398v1))

**第三层：统一成 instance-level pixel masks。**
因此 SUIM 的 semantic mask 要转成 instance；USIS10K/USIS16K 只有 salient instances 的问题也需要补充/重新核对；UIIS/UIIS10K 原本是 general instance，主要是类别重新细化。论文只笼统说“systematically re-annotate and extend”，没有像 UIIS10K 那篇那样把每种来源的补标流程逐项公开。([arXiv](https://arxiv.org/html/2510.15398v1))

**第四层：重新组织 superclass taxonomy。**
MARIS 最终不是照搬 USIS16K 的 11 个 superclass，而是整理成 **9 个 superclass**：

Human、Fish、Non fish、Marine Garbage、Wrecked Vehicle、Lost item、Archeology、Underwater equipment、Underwater operation。([arXiv](https://arxiv.org/html/2510.15398v1))

这说明所谓 “based on [13]” 更准确地说是：**主要继承 USIS16K 的 158 类细粒度 taxonomy，再按照 MARIS 的 OVIS 任务重新组织父类与实例标注。**

## 7. 你问的“一张图包含多个种类”——目前论文真正告诉我们的是什么？

这是这里最需要谨慎的地方。

MARIS 明确说，原计划按照类别划分 train/val，但因为**一张图存在 multiple instances**，最后产生了类别交叉：5,712 train images、10,439 val images；84 个类别出现在 train，115 个出现在 val，其中 41 个重叠，最终 43 train-only、74 validation-only/OV classes。([arXiv](https://arxiv.org/html/2510.15398v1))

但论文**没有给**：

```
一张图只有1个类别：X张`
`2个不同类别：Y张`
`≥3个不同类别：Z张
```

这种统计。

而且作者的 “multiple instances per image” **不能翻译成“多类别图像”**。这是两个完全不同的统计量。

MARIS 公开的类别分布主要是 **instance-per-class distribution**：它是明显的长尾分布，common reef fish 等常见物种拥有较多实例，一些 rare species 少于 **60 个 instances**；74 个 unseen/OV 类自身的频次差别也非常大。([arXiv](https://arxiv.org/html/2510.15398v1))

所以如果你现在关心的是 **MARIS 是否适合研究“同一张图中多物种/多类别竞争”**，论文给的信息还不够。官方已经公开 COCO-format 的 `instances_train.json` 和 `instances_val.json`，文件分别约 47.9 MB 和 75.7 MB，因此这个数其实可以直接从 annotation 精确统计出来。([Hugging Face](https://huggingface.co/datasets/kkk2026/WaterOVS/tree/main/annotations))

统计时真正应该算的是：

$$
N_{\text{multi-class}} 

\sum_i
\mathbf 1
\left(
|{category_id_j:j\in image_i}|>1
\right),
$$

而不是数 `annotations per image > 1`。

### 最值得你记住的一张“血缘图”

```text
EUVP / USR-248 / UFO-120
          ↓
         SUIM
          ↓
          ├─────────────────────┐

UIEB / Berman ──→ USIS10K ←── UIIS/WaterMask
       ↑              ↓             ↓
       │              └────→ UIIS10K ←── SUIM / TrashCan / USOD10K
       │                         ↑
USOD10K ───────→ USIS16K         │
                    ↓             │
                    └──────┬──────┘
                           ↓
                         MARIS
              统一重标 + 158细粒度类别
                9 superclass / instance masks
```

所以**MARIS 的价值并不主要在“又采了 16K 张新水下照片”**。它真正做的数据集贡献是：把此前分散在 semantic segmentation、general instance segmentation、salient instance segmentation 中的水下图像资源，**重新组织成适合 Open-Vocabulary Instance Segmentation 的 158 类细粒度 instance benchmark**。从你做水下开放词汇分割的角度，这一点比“16K 张”本身更关键。([arXiv](https://arxiv.org/html/2510.15398v1))

有。按“类别丰富度”看，除了 USIS16K/AquaOV255，最值得关注的是 **FathomNet 新发布的分割标注**；按“拿来即可做水下开放词汇实例分割 benchmark”看，则还是 **MARIS** 最成熟。

### 我的建议

如果你追求“类别尽量丰富”，优先采用：

> **FathomNet 筛选子集作为训练集 + MARIS/SeaClear/Seatizen 作为测试集**

具体可以这样设计：

1. 从 FathomNet 的1,993个 concept 中筛选约 **150–300类**。
2. 每类至少保留 **30或50个实例**，去掉极端长尾类。
3. 统一标签层级：不要同时把 `fish—shark—great white shark` 当成三个互斥平面类别；建议主要保留 species，无法到 species 的统一退到 genus 或形态类。
4. 按视频、潜次、采集机构或地理区域划分，而不是随机拆帧，避免近重复图像泄漏。
5. 另外构造一个 **family-disjoint novel split**：同一科或同一属的类别全部放在 base 或 novel 一侧，这比随机类别划分更能证明开放词汇泛化能力。

需要特别注意：FathomNet 虽然类别极多，但它不是天然整理好的“1,993类 COCO”。concept 存在分类层级、同义名和长尾问题，且不同贡献者的[许可条件可能不同](https://www.fathomnet.org/terms)。因此它非常适合做训练池或构建新数据集，但不建议未经清洗直接作为正式 benchmark。

如果只选一个：

- **想直接跑论文实验：MARIS。**
- **想构建真正类别丰富、区别于现有工作的数据集：FathomNet。**
- **如果训练已经用了 USIS16K/AquaOV255：不要把 MARIS 宣称为完全独立测试集，优先用 SeaClear、Seatizen、COU 或 TrashCan 做外部测试。**
